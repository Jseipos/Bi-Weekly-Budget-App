## Commands

```bash
npm run dev              # Next.js dev server (http://localhost:3000)
npm run build            # Production build
npm run start            # Run production build
npm run lint             # ESLint (eslint-config-next)

npx vitest               # Run all tests (watch mode)
npx vitest run           # Run all tests once
npx vitest run src/lib/__tests__/debt-calc.test.ts   # Single test file
npx vitest run -t "name"                              # Filter by test name

npx drizzle-kit generate # Generate a new SQL migration from schema.ts
npx drizzle-kit migrate  # Apply pending migrations to DATABASE_URL
npx drizzle-kit studio   # Open Drizzle Studio against the SQLite db
```

Docker (production self-host, see DEPLOY.md for full guide):

```bash
docker compose up -d --build   # Build + start
docker compose logs -f         # Tail logs
git pull && docker compose up -d --build   # Update in place; ./data volume is preserved
```

## Architecture

Single-user self-hosted **Next.js 16 (App Router) + React 19** budget planner. Data lives in **SQLite via better-sqlite3**, accessed through **Drizzle ORM**. Styling is **Tailwind v4**. Tests use **Vitest**. Runs in Docker Compose on a Mac with iCloud Drive bind-mounted for receipt storage; remote access is via Cloudflare Tunnel or Tailscale (see DEPLOY.md).

### Authentication — PIN + HMAC cookie, split between Node and Edge

Auth is intentionally minimal because this is a single-user app on a private network. There is no user table — a single PIN hash is stored in the `settings` table (key/value), and bcrypt is used to verify it (`src/actions/auth.ts`). Default PIN is `0000`.

Sessions are a plain `budget_session` cookie whose value is `<uuid>.<hmac-sha256(uuid, SESSION_SECRET)>`. Important constraint: `src/middleware.ts` runs on the **Edge runtime** which does not have Node `crypto`, so middleware only does a cheap format/existence check on the cookie and redirects to `/` if missing. **Real HMAC verification happens in `src/lib/auth.ts` (`verifyToken`, `isAuthenticated`), which is called from server actions and server components**. When adding a new protected area, update both the middleware `matcher` and call `isAuthenticated()` in the server component/action — do not rely on middleware alone.

### Route layout

- `src/app/page.tsx` — login (PIN entry, public)
- `src/app/(protected)/` — protected route group: `dashboard`, `spending`, `recurring`, `debts`, `settings`. Shared `layout.tsx` here wraps with `NavBar`.
- Middleware `matcher` in `src/middleware.ts` lists these paths explicitly — **keep it in sync** with `(protected)/` folders.

### Data flow — server actions, not API routes

There are no `app/api/*` routes. All mutations go through **server actions** in `src/actions/` (`spending.ts`, `recurring.ts`, `debts.ts`, `categories.ts`, `dashboard.ts`, `auth.ts`). Client components import these directly and call them as async functions. When adding functionality, follow this pattern rather than creating API handlers.

### Database

- Schema: `src/db/schema.ts` — five tables: `settings`, `recurring_items`, `unplanned_expenses`, `categories`, `debts`, `debt_payments`. Dates stored as ISO `YYYY-MM-DD` text; booleans as integers via Drizzle's `mode: "boolean"`.
- Client: `src/db/index.ts` (better-sqlite3 + drizzle)
- Seed: `src/db/seed.ts`
- Migrations: `drizzle/` directory, generated by `drizzle-kit` from `schema.ts`. The live db file is `./data/budget.db` on the host, mounted into the container at `/app/data/budget.db`.

### Pure logic lives in `src/lib/` and is tested

Non-trivial calculations are isolated in `src/lib/` so they can be unit-tested without the Next/React/DB stack:

- `debt-calc.ts` — avalanche/snowball debt payoff simulation (used by `DebtSimulation.tsx`)
- `date-calc.ts` — recurring-item date math across frequencies
- `predictions.ts` — forward-looking monthly budget projections
- `receipt-storage.ts` — maps uploaded receipts into category-specific iCloud subfolders

Corresponding tests in `src/lib/__tests__/`. When changing behavior in these files, update/add tests there; avoid pushing this logic into components or server actions.

### Receipt storage and iCloud

Receipts uploaded through `unplanned_expenses` are written to category-mapped folders under the iCloud mount (`ICLOUD_BASE_PATH`, default `/app/icloud` in the container → `~/Library/Mobile Documents/com~apple~CloudDocs` on the host). Each category row in `categories` has an optional `icloudFolderPath`; `receipt-storage.ts` resolves the destination. Files therefore sync to every Apple device on the same iCloud account without any app-side sync code. `MAX_UPLOAD_SIZE` caps the upload.

### Path alias

`@/*` → `./src/*` (set in both `tsconfig.json` and `vitest.config.ts`).

## Environment

Required in `.env.production` for Docker, `.env` for local dev:

- `SESSION_SECRET` — **must** be set in production (`openssl rand -hex 32`). Falls back to a dev default otherwise.
- `DATABASE_URL` — path to SQLite file. Defaults to `./data/budget.db`.
- `ICLOUD_BASE_PATH` — host iCloud Drive root; bind-mounted into container.
- `MAX_UPLOAD_SIZE` — bytes, default 10 MB.
